# 对话式康复陪练机器人

一个面向老年人、残障人士和运动功能障碍人群的康复训练陪伴原型。项目结合规则状态机、生成式 AI、语音交互和动作动画，引导用户完成简单的手部与上肢训练。

> 核心思路：让规则决定“做什么”，让大模型优化“怎么说”。

## 项目能做什么

- 引导完成手指张合、手腕屈伸、桌面触点等基础训练；
- 使用状态机管理动作说明、训练计数、休息、继续和结束；
- 通过浏览器提供文字输入、语音识别和中文语音播报；
- 使用机器人表情和动作动画提供更直观的反馈；
- 识别疼痛、头晕、胸闷等风险表达，并立即停止训练；
- 使用 OpenAI 或 Claude 润色固定话术、回应简单闲聊；
- 未配置 API Key 或模型不可用时，自动使用本地兜底话术。

## 为什么采用“规则 + 大模型”

康复训练需要稳定、明确的流程，不能让大模型自由决定动作、次数或医疗建议。因此，本项目将职责分开：

| 模块 | 职责 |
| --- | --- |
| 规则状态机 | 决定训练动作、次数、流程和进度 |
| 安全规则 | 优先检测不适信号并停止训练 |
| JSON 动作库 | 保存动作步骤、目标次数和动画类型 |
| 大模型 | 润色表达并处理普通闲聊 |
| Flask + 网页前端 | 提供接口、动画、语音和交互界面 |

这种设计让训练逻辑保持可控，同时保留自然、温和的对话体验。

## 快速开始

### 1. 获取项目

```bash
git clone https://github.com/xr-hci/rehab_chatbot.git
cd rehab_chatbot
```

### 2. 安装依赖

建议使用 Python 3.10 或更高版本，并创建独立虚拟环境：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows 激活虚拟环境可使用：

```powershell
.venv\Scripts\activate
```

### 3. 配置大模型（可选）

本仓库不提供作者的 API Key。每位使用者需要配置自己的 Key，相关模型调用计入使用者自己的服务商账户。

复制配置示例：

```bash
cp .env.example .env
```

Windows PowerShell 可使用：

```powershell
Copy-Item .env.example .env
```

在 `.env` 中填写自己的 OpenAI API Key：

```dotenv
OPENAI_API_KEY=your_openai_api_key_here
```

也可以配置 `ANTHROPIC_API_KEY` 使用 Claude。若两个 Key 都存在，项目优先使用 OpenAI。

### 4. 启动

```bash
python app.py
```

在浏览器中打开 <http://127.0.0.1:5030>。

## 项目结构

```text

├── app.py                 # Flask 服务、会话隔离和接口保护
├── agent.py               # 对话状态机、意图识别和训练逻辑

├── requirements.txt       # Python 依赖
├── share.command          # macOS 临时公网分享脚本
└── templates/
    └── index.html         # 机器人界面、动画和语音交互
```

完整的设计思路、系统架构、状态机和安全机制请阅读 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md)。

## API Key 与运行模式

### 配置 API Key

系统会使用大模型润色训练话术，并提供更自然的日常对话能力。模型调用产生的用量由使用者自己的 API 账户承担，不会使用作者的账户或额度。

### 不配置 API Key

项目仍然可以启动。训练选择、动作说明、完成计数、休息、继续和安全停止等基础流程均可使用，但系统会采用本地固定话术，AI 润色和开放式闲聊能力不可用。

### Key 安全说明

- `.env` 已被 `.gitignore` 排除，不会随正常的 Git 提交上传；
- 仓库只包含不带真实密钥的 `.env.example`；
- API Key 仅由后端读取，不会发送到浏览器前端；
- 请勿将 Key 写入 Python、HTML、截图、日志或 Git 提交信息；
- 当前训练会话只保存在运行机器的内存中，服务重启后清空。

如果某个 Key 曾出现在公开提交、截图或日志中，仅删除文件并不安全；应立即在服务商后台撤销旧 Key，并生成新 Key。

## 当前边界
